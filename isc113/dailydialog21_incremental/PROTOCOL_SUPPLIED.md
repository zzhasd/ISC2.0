# 31 段 DailyDialog 长对话的逐轮属性预测累积实验方案

实验协议 V1.0｜基于 AGD-EVAL（2026-11-06）｜Direct Thinking vs. ELARA v1

## 一、研究目标与实验定位

### 1.1 实验名称

基于 AGD-EVAL 的长对话逐轮信息累积与属性发现动态研究：Direct Thinking 和 ELARA v1 的比较

英文可命名为：

Incremental Attribute Discovery in Long Dialogues: A Prefix-Based Evaluation of Direct Thinking and ELARA v1 Using AGD-EVAL

### 1.2 核心研究问题

本实验研究：随着长对话中可见说话者 A 的发言逐轮累积，模型能够预测多少关于隐藏说话者 B 的属性？这些预测数量的增加是否意味着有效属性发现能力的提升？

需要区分三个研究层次。

| 研究层次 | 研究问题                      | 对应核心指标    |
| ---- | ------------------------- | --------- |
| 数量增长 | 随着 A 发言增加，算法输出多少条 B 属性预测？ | 原始预测数     |
| 有效发现 | 增加的预测中有多少属于当前证据支持的不同属性？   | 有效唯一属性数   |
| 边际发现 | 新增一条 A 发言后，算法首次发现多少新属性？   | 每轮首次新增属性数 |

再通过两个算法之间的配对比较，研究 ELARA v1 在累积对话信息方面是否表现出不同于 Direct Thinking 的增长规律。

### 1.3 研究假设

建议提前冻结三个假设：

H1：属性发现增长假设

随着 A-only 前缀长度增加，两种算法的平均有效唯一属性数量总体呈增长趋势。

H2：ELARA 相对增长优势假设

随着可见发言增多，ELARA v1 相对 Direct Thinking 的有效唯一属性发现数量优势扩大。

H3：边际发现机制假设

两算法对逐轮新增信息的利用存在差异，ELARA v1 可能通过更多 E2 隐式证据支持的属性获得额外发现量。

其中 H1–H3 均作为待检验假设，而不是预设结论。

特别需要注意，本实验只研究长度恰好为 21 条的对话，检验的是同一长度类别内的信息累积效应，不是长对话和短对话之间的直接比较。

## 三、实验一：构建逐轮累积的 A-only 前缀

### 3.1 前缀定义

对于第 \\(i\\) 段对话，定义：

\\[ D_i=(A_1,B_1,A_2,B_2,\ldots,A\_{10},B\_{10},A\_{11}) \\]

在第 \\(k\\) 次观察时，模型能够看到的内容为：

\\[ X\_{i,k}=(A_1,A_2,\ldots,A_k) \\]

其中：

\\[ k\in\\{1,2,\ldots,11\\} \\]

具体的 11 个观察点为：

| 前缀 k | 原始对话中可见的发言编号      | A 发言数 |
| ---- | ----------------- | ----- |
| 1    | 1                 | 1     |
| 2    | 1, 3              | 2     |
| 3    | 1, 3, 5           | 3     |
| 4    | 1, 3, 5, 7        | 4     |
| 5    | 1, 3, 5, 7, 9     | 5     |
| 6    | 1, 3, 5, 7, 9, 11 | 6     |
| 7    | 1, 3, …, 13       | 7     |
| 8    | 1, 3, …, 15       | 8     |
| 9    | 1, 3, …, 17       | 9     |
| 10   | 1, 3, …, 19       | 10    |
| 11   | 1, 3, …, 21       | 11    |

因此总前缀数为：

\\[ 31\times11=\boxed{341} \\]

每个前缀在两个算法和 AGD-EVAL 中使用完全相同的可见发言集合。

### 3.2 推荐输入格式

可以沿用 ISC113 的 `visible_turns` 结构。

例如第 3 个前缀：

```
{
  "dialogue_id": "train_988",
  "prefix_k": 3,
  "direction": "A_to_B",
  "visible_turns": [
    {"turn_id": 1, "text": "A的第一条发言"},
    {"turn_id": 3, "text": "A的第二条发言"},
    {"turn_id": 5, "text": "A的第三条发言"}
  ]
}
```

格式示例；文本为占位内容，不是真实对话。

建议额外建立稳定的前缀 ID：

```
train_988__k01
train_988__k02
...
train_988__k11
```

这个 ID 将作为 AGD-EVAL 的独立评价任务标识。

### 3.3 前缀生成的检查条件

正式推理前，必须自动验证：

1. 恰好有 31 个不同的原始对话 ID。
2. 每段完整对话恰好 21 条发言。
3. 每段生成 11 个连续前缀。
4. 每个前缀只包含奇数编号发言。
5. 第 k 个前缀恰好包含 k 条 A 发言。
6. 第 k−1 个前缀的发言序列是第 k 个前缀的严格前缀。
7. 所有 341 个前缀 ID 唯一。

另外，31 段对话在 k=11 时的最终 A-only 输入，可以作为一致性检查：最后一个前缀应与该段对话的完整 A-only 输入完全相同。

## 四、实验二：两个预测算法的逐前缀独立运行

### 4.1 算法设置

本实验只包含两种算法：

| 设置               | Direct Thinking | ELARA v1 |
| ---------------- | --------------- | -------- |
| 预测目标             | B 属性            | B 属性     |
| 可见信息             | A₁…Aₖ           | A₁…Aₖ    |
| 前缀数量             | 341             | 341      |
| 是否读取 B 发言        | 否               | 否        |
| 是否读取前一轮预测        | 否               | 否        |
| 是否读取 AGD-EVAL 结果 | 否               | 否        |
| 是否保留原始算法逻辑       | 是               | 是        |

主实验必须独立重运行，而不是增量更新已有预测。

例如：

- k=3 时，从 A₁、A₂、A₃ 重新预测一次。
- k=4 时，从 A₁、A₂、A₃、A₄ 重新预测一次。
- k=4 不应读取 k=3 已经生成的 claims。

这样避免历史预测内容本身成为新输入，污染对对话累积信息的研究。

### 4.2 Direct Thinking 配置

从上传的 ISC113 文件中可以核对到，原始 Direct Thinking 使用：

| 参数              | 原始设置            |
| --------------- | --------------- |
| 模型              | `qwen3.8-flash` |
| temperature     | 0（非采样模式）        |
| thinking        | 开启              |
| thinking_budget | 512             |
| 原始 claim 上限     | 10              |
| 生成上限            | 2,048 tokens    |

正式实验建议保留这套设置，以保证研究对象仍是 ISC113 的 Direct Thinking，而不是经过重新设计的版本。

### 4.3 ELARA v1 配置

ELARA v1 需要保留原始候选生成、证据组织和属性筛选逻辑。

目前上传的 ISC113 压缩包提供了 ELARA v2、v3 的实现，以及 ELARA v1 的历史输出，但未找到能够直接确认其完整在线运行配置的 v1 脚本。

因此，正式运行前必须补齐：

- ELARA v1 原始推理代码。
- 原始提示词。
- Qwen 模型版本与推理参数。
- 内部模型调用阶段。
- 输出数量与 token 上限。

不能用 ELARA v2、v3 代替 v1，或者根据历史输出反推并重写一个所谓的 v1。

### 4.4 输出数量上限的处理

之前发现 Direct Thinking 最多输出 10 条原始 claims，而 ELARA v1 的历史输出存在多于 10 条的情况。

这可能影响本次实验的数量增长曲线。

我建议采用以下设计：

主实验：原样保留两算法。

目的在于研究原始算法在相同 A-only 前缀下的真实输出表现。

同时记录每个前缀：

- 原始 claim 数。
- 是否达到算法上限。
- 输入和输出 token 数。
- 是否发生格式校验失败。
- 是否发生因输出长度导致的截断。

敏感性实验：仅在需要时放宽 Direct Thinking 的 10 条限制。

例如统一允许最多 20 条 claims，研究 Direct 的曲线是否因此继续增长。但这属于修改后算法，必须单独报告，不能混入主实验。

### 4.5 预测输出

每一个前缀、每一种算法保存一个独立结果。

建议采用：

```
{
  "dialogue_id": "train_988",
  "prefix_k": 3,
  "algorithm": "direct_thinking",
  "claims": [
    {
      "claim": "B ...",
      "evidence": [
        {"turn_id": 3}
      ],
      "confidence": 0.87
    }
  ],
  "usage": {},
  "run_config": {}
}
```

其中属性内容、证据和置信度只是字段示意；实际应保留算法原生输出，不要求两个算法都生成其原本不提供的字段。

模型输出的自引证据只能作为审计材料，不直接作为 AGD-EVAL 判定属性有效的依据。

每个前缀两个算法合计产生：

\\[ 341\times 2=\boxed{682\text{ 个预测结果}} \\]

这里的 682 是逻辑预测任务数。若 ELARA v1 内部每个前缀需要多次模型调用，真实推理 API 请求数量会更高。

## 五、实验三：针对 341 个前缀运行 AGD-EVAL

这是整个实验的核心。

建议沿用 2026-11-06 版本的 AGD-EVAL 判断标准和计分规则，将其数据组织方式从“每段完整对话评价一次”改为“每个 A-only 前缀评价一次”。

### 5.1 整体流水线

第 i 段对话，第 k 个 A-only 前缀

仅包含 A₁…Aₖ

预测分支

Direct + ELARA 输出

独立发现分支

AGD Sweep

AGD Atomic Support

候选断言原子化、E1/E2/E3/E4 等证据审核

AGD Pool(i,k)

构建当前前缀的共享规范事实池

AGD Score(i,k)

两算法使用相同事实池计算指标

跨前缀事实对齐与轨迹分析

首次发现、保留、消失、重新出现及 slot 细化

注意：同一前缀只运行一次共同的 Sweep 和 Pool，而不是 Direct 和 ELARA 分别运行各自的 Sweep 和 Pool。

这既保证评价口径一致，也能减少调用成本。

### 5.2 第一步：Independent Sweep

输入：当前前缀的 A-only 发言。

例如：

\\[ X\_{i,4}=(A_1,A_2,A_3,A_4) \\]

独立 Sweep 负责尽可能完整、保守地发现当前文本能够支持的 B 属性。

它必须遵守：

- 不能读取 Direct Thinking 的预测。
- 不能读取 ELARA v1 的预测。
- 不能读取隐藏 B 发言。
- 不能读取未来 A 发言。
- 只能使用当前前缀中的 E1/E2 证据发现事实。

输出记为：

\\[ S\_{i,k}=\operatorname{Sweep}(X\_{i,k}) \\]

例如可以独立发现职业、关系、偏好、已发生事件、当前状态等有证据支持的事实。

但不能仅凭开放性问题或常见对话情境推测 B 的具体属性。

#### 是否需要每个前缀重新 Sweep？

需要。

不能只对完整 A₁…A₁₁ 运行一次 Sweep，然后直接把结果分配给前面的所有前缀。

原因是，完整对话中的后续证据可能改变早期事实的判断。

不过，技术上可以缓存已经完成的模型输出，并对相同候选的历史审核结果进行确定性复用；所有前缀仍须保留完整的独立判断记录。

本实验的 Sweep 调用预算为：

\\[ N\_{\text{sweep}}=341 \\]

每个前缀一次，失败重试除外。

### 5.3 第二步：Atomic Support

这一阶段对三个来源的候选进行审核：

\\[ C\_{i,k} = P^{D}\_{i,k} \cup P^{E}\_{i,k} \cup S\_{i,k} \\]

其中：

- \\(P^D\\)：Direct Thinking 原始预测。
- \\(P^E\\)：ELARA v1 原始预测。
- \\(S\\)：独立 Sweep 结果。

审核前需要对预测候选进行精确文本规范化去重，保留原始预测到候选 ID 的映射。

所有候选进行来源盲化，避免评价器因为知道某条预测来自 ELARA 或 Direct 而产生偏差。

AGD-EVAL 的 Support 阶段需要完成两个任务：

任务 A：原子化

将一个可能包含多个独立命题的 claim 拆成多个原子断言。

例如：

> B 是护士，并且在医院工作了三年。

可拆分为：

- B 是护士。
- B 在医院工作。
- B 已在医院工作三年。

原子化时不能删除原 claim 中尚未被支持的具体内容，也不能把没有证据的强断言改写成容易获得支持的弱断言。

任务 B：证据判定

依据当前 A-only 前缀对每个原子断言赋予证据标签。

| 标签           | 判定含义                   | 进入事实池 |
| ------------ | ---------------------- | ----- |
| E1           | A 直接明确地表达 B 的属性        | 是     |
| E2           | A 的预设、语用、指代或跨轮证据足够强地支持 | 是     |
| E3           | 有相关线索，但不足以支持该断言        | 否     |
| E4           | 没有相关证据                 | 否     |
| CONTRADICTED | 当前 A 证据否定该断言           | 否     |
| NOT_B        | 断言不是关于 B 的实质属性         | 否     |
| UNCERTAIN    | 无法可靠判定，需要人工复核          | 暂不进入  |

保留 AGD-EVAL 的原有标准：

\\[ \text{Valid}=\\{\text{E1},\text{E2}\\} \\]

特别注意：E3 不能因为预测内容与完整对话中 B 的真实情况一致，就变成有效预测。判断依据始终是当前 A-only 前缀。

#### 审核批次

沿用原始配置：

\\[ \text{batch\\\_size}=12 \\]

也就是每次评价模型请求最多审核 12 个候选 claim。

假设某个前缀有：

- Direct 输出 6 条；
- ELARA 输出 11 条；
- 合并精确重复文本后，Pred 剩下 15 条；
- Sweep 发现 7 条。

那么：

\\[ N\_{\text{pred-support}}=\lceil15/12\rceil=2 \\]

\\[ N\_{\text{sweep-support}}=\lceil7/12\rceil=1 \\]

这部分调用量不是固定的，而是取决于模型实际产生的候选数量。

### 5.4 第三步：构建前缀规范事实池

每个前缀都必须构建一个独立的规范事实池：

\\[ G\_{i,k}=\operatorname{Pool}(E^{\text{valid}}\_{i,k}) \\]

其中 \\(E^{\text{valid}}\_{i,k}\\) 是该前缀经审核为 E1/E2 的原子断言集合。

池中需要保存：

- `fact_id`：前缀内的事实 ID。
- `canonical_claim`：规范事实表述。
- `level`：E1 或 E2。
- `slots`：事实的核心及补充字段。
- `members`：哪些原子断言支持该规范事实。
- 每个 member 覆盖的具体 slot。

举例：

一个规范事实的示例

Canonical fact

B 在一家医院担任护士，已经工作三年。

| Slot | 值     | 权重 |
| ---- | ----- | -- |
| 核心关系 | 在医院工作 | 2  |
| 职业   | 护士    | 1  |
| 时间长度 | 三年    | 1  |

仅为结构示意。实际核心字段划分、事实合并范围及支持性均由审核规则决定，不能根据该示例固定。

正式实验沿用 AGD-EVAL 2026-11-06 版本已经冻结的字段计分规则：

- 所有实际成立的 slots 均为 required。
- 核心 slot 权重为 2。
- 其他 slot 权重为 1。
- 预测只覆盖自己实际表达的字段，不因为归入同一 fact 就自动获得其他字段。

#### 341 个前缀事实池

\\[ 31\times11=\boxed{341} \\]

每个事实池对应一个完整的当前信息状态。

例如：

| 对话          | k  | Pool   |
| ----------- | -- | ------ |
| Dialogue 1  | 1  | G₁,₁   |
| Dialogue 1  | 2  | G₁,₂   |
| …           | …  | …      |
| Dialogue 1  | 11 | G₁,₁₁  |
| Dialogue 2  | 1  | G₂,₁   |
| …           | …  | …      |
| Dialogue 31 | 11 | G₃₁,₁₁ |

如果某个前缀没有任何有效原子属性，该前缀的 Pool 就为空。

空 Pool 是合法实验结果，不能删除该前缀，也不需要为了满足数量要求强行生成属性。

### 5.5 新数据集没有旧 Gold，应如何处理？

这是与原 ISC113 主评价的一个区别。

在 AGD-EVAL 原始代码中，事实池来源包含：

\\[ \text{Pred}+\text{Gold}+\text{Sweep Support} \\]

但这 31 段是从完整 DailyDialog 中新选取的样本，并没有现成的 ISC113 Gold 标注。

因此本次实验建议采用：

\\[ \boxed{ G\_{i,k}= \operatorname{Pool} ( \text{Pred}\_{E1/E2} \cup \text{Sweep}\_{E1/E2} ) } \\]

不能直接把不存在的 Gold 当成已经标注完成的真实属性集。

这里有三个实现要求：

1. 对 AGD-EVAL 数据准备代码进行最小适配，让 `references=[]` 合法。
2. 保持 `gold` 审核阶段的空结果占位，使现有 Pool 和 Score 逻辑能够正常执行。
3. 将 `new_vs_gold` 和依赖旧 Gold 的新颖性指标标记为不适用于本实验，不能把所有有效发现误报为“相对于旧 Gold 的新增事实”。

这里的修改属于新数据集适配，不是改变 E1/E2 的判断标准。

建议保留源码修改记录和版本哈希，确保之后能够重新复现实验。

### 5.6 建议增加独立 Sweep 事实池用于敏感性分析

共享事实池中的有效事实来自两个算法与 Sweep。

它适合沿用 AGD-EVAL 的原有评价方式，但可能存在候选来源影响评价分母的问题。

因此额外记录：

\\[ G^{S}\_{i,k}= \operatorname{Pool}(\text{Sweep}\_{E1/E2}) \\]

作为独立 Sweep 事实子集。

主评价仍使用两算法共享事实池；补充评价再使用 Sweep 来源的事实子集检查：

“ELARA 在共享池中表现出的有效属性发现优势，是否依然能体现在独立发现的事实集合上？”

这样有助于避免只因为 ELARA 贡献了更多候选事实，就产生过强的召回率结论。

同时需要承认，Sweep 不是绝对完整的事实真值集合，它也可能漏掉可支持事实。

## 六、实验四：31 个跨前缀统一事实索引

只构建 341 个前缀事实池，还不能直接计算“首次新增属性数”。

原因是每个前缀内的 `fact_id` 都是局部编号。

比如第 4 个前缀中的 `f1`，并不一定是第 5 个前缀中的 `f1`。

因此必须进行跨前缀事实身份对齐。

### 6.1 每段对话建立一个统一事实索引

对第 \\(i\\) 段对话，收集它的 11 个前缀事实池：

\\[ G\_{i,1},G\_{i,2},\ldots,G\_{i,11} \\]

建立：

\\[ U_i=\operatorname{Align}(G\_{i,1},\ldots,G\_{i,11}) \\]

最终共建立：

\\[ \boxed{31\text{ 个跨前缀统一事实索引}} \\]

每个索引中的规范事实可以拥有稳定 ID，例如：

```
train_988::u001
train_988::u002
train_988::u003
```

之后将所有前缀中的局部事实 ID 映射到统一 ID。

### 6.2 具体如何匹配？

建议将跨前缀匹配分为以下三种情况：

| 情况   | 示例                    | 处理方式                     |
| ---- | --------------------- | ------------------------ |
| 同义重复 | “B 在医院工作”与“B 就职于一家医院” | 合并为同一事实                  |
| 信息细化 | “B 在医院工作”与“B 在医院担任护士” | 根据关系及事件身份判断是否属于同一事实的字段扩充 |
| 不同属性 | “B 是护士”与“B 喜欢音乐”      | 保持不同事实                   |

需要特别避免过度合并。

例如，“B 曾在医院工作”和“B 目前在医院工作”可能具有不同的时间状态。如果当前证据不能证明它们是同一个事件，就不能因为两句话都出现“医院工作”而强制合并。

推荐保留每个事实的：

- 主体及关系。
- 关键对象。
- 时间和事件身份。
- 否定状态。
- 事件是否已经发生。
- 证据等级。
- 具体字段。

### 6.3 跨前缀对齐是否会发生未来信息泄露？

如果处理得当，不会。

关键是严格区分两个任务：

任务 A：证据有效性判断。

只能使用当前前缀 A₁…Aₖ。

任务 B：规范事实身份对齐。

可以在离线分析时查看本段对话全部 11 个前缀的规范事实表述，以便识别“这是不是同一个属性”。

但对齐不能把未来事实、未来字段或未来 E1/E2 判定回填到早期前缀。

例如，第 3 个前缀没有证据支持“B 工作三年”，第 7 个前缀才有支持。

即使两个前缀的事实后来被统一到同一规范 ID，也不能把“三年”字段记为第 3 个前缀已经发现。

## 七、实验指标体系

我建议将指标分为三个主指标、四个辅助指标和三个诊断指标。

### 7.1 主指标一：原始属性预测数量

定义：

\\[ N^{\text{raw}}\_{i,m,k} = |P^{\text{raw}}\_{i,m,k}| \\]

其中：

- \\(i\\)：第 i 段对话，1–31。
- \\(m\\)：Direct Thinking 或 ELARA v1。
- \\(k\\)：前缀长度，1–11。

这一指标统计模型实际输出了多少条 claim，不考虑是否有证据，也不对重复文本做去重。

例如：

- Direct 输出 5 条，则 \\(N^{raw}=5\\)。
- ELARA 输出 9 条，则 \\(N^{raw}=9\\)。

即使其中有两条语义重复，也都计入原始数量。

这直接对应你的研究题目——属性预测数量随对话累积的变化。

### 7.2 主指标二：有效唯一属性数量

定义：

\\[ V\_{i,m,k} = \left\\{ u\in U_i: \begin{array}{l} u\text{ 在前缀 }k\text{ 有 E1/E2 支持，}\\\ m\text{ 的预测覆盖 }u\text{ 的全部 core slots} \end{array} \right\\} \\]

那么：

\\[ N^{\text{unique}}\_{i,m,k} = |V\_{i,m,k}| \\]

这是本实验最重要的质量调整后的数量指标。

例如，模型原始输出 10 条 claims，其中：

- 6 条完全有据。
- 2 条重复同一个属性。
- 2 条无足够证据。

经过原子化、证据审核和规范事实合并后，可能只覆盖 5 个不同的有效事实核心。

因此：

\\[ N^{raw}=10,\quad N^{unique}=5 \\]

需要注意，有效唯一属性数不必等于完全有效原始 claim 数。一条混合了有据与无据断言的 claim，虽然不能计入完全有效原始 claim，但其中经过单独审核有效的原子断言仍可能贡献一个规范事实核心。

这与 AGD-EVAL 的原子化评分思想一致。

### 7.3 主指标三：每轮首次新增属性数

定义：

\\[ N^{new}\_{i,m,k} = \left| V\_{i,m,k}\setminus \bigcup\_{j=1}^{k-1}V\_{i,m,j} \right| \\]

对于 k=1，首次新增数就是该前缀已经发现的有效唯一属性数。

对于 k≥2，只有此前从未有效预测过的规范事实核心才算首次新增。

同时建议计算累计曾发现数量：

\\[ N^{ever}\_{i,m,k} = \left|\bigcup\_{j=1}^{k}V\_{i,m,j}\right| \\]

二者关系为：

\\[ N^{ever}\_{i,m,k} = \sum\_{j=1}^{k}N^{new}\_{i,m,j} \\]

这条关系应作为程序输出的自动一致性检查。

### 7.4 辅助指标

| 指标                     | 计算方式                                            | 解释          |
| ---------------------- | ----------------------------------------------- | ----------- |
| \\(P\_{\text{raw}}\\)  | 完全有据的原始 claims / 全部原始 claims                    | 预测有效比例      |
| \\(R\_{\text{core}}\\) | 已发现有效事实核心 / 当前事实池全部核心                           | 当前可支持事实的发现率 |
| E1/E2 数量               | 分别统计证据等级下的有效唯一属性                                | 显式与隐式属性贡献   |
| Slot Coverage          | 已覆盖 required slots 的加权和 / 全部 required slots 权重和 | 属性细节恢复能力    |

其中：

\\[ R\_{\text{core},i,m,k} = \frac{N^{unique}\_{i,m,k}}{|G\_{i,k}|} \\]

仅在事实池非空时定义。事实池为空时，应记录为缺失值，而不是人为设置为 0 或 1。

为了沿用 AGD-EVAL 原始报告口径，汇总 \\(P\_{\text{raw}}\\) 和 \\(R\_{\text{core}}\\) 时，建议优先采用微平均，即先汇总分子和分母，再计算比例。

但是对于属性数量增长曲线，则使用 31 段对话的均值，不采用把所有 claims 汇总后直接相加的方式。

### 7.5 诊断指标

建议保留以下三个：

A. 输出上限触达率

\\[ C_m(k)= \frac{\sum\_{i=1}^{31}I(N^{raw}\_{i,m,k}\geq L_m)}{31} \\]

其中 \\(L_m\\) 是算法实际配置的 claim 上限。Direct 原始上限为 10；ELARA 的上限待原始实现确认后填写。

这个指标能帮助判断后期数量平台是否来自输出限制。

B. 当前预测净变化

\\[ \Delta N\_{i,m,k} = N^{unique}\_{i,m,k}-N^{unique}\_{i,m,k-1} \\]

净变化可以为负，首次新增数不会为负。

C. 冗余与无效预测

继续沿用 AGD-EVAL 的：

- `semantic_redundant_valid_rate`
- `unsupported_raw_rate`
- `exact_text_repetition_rate`

但不要把不同的重复概念混为一谈：相同文本重复、语义重复、以及重复覆盖同一事实核心，是不同层次的现象。

### 7.6 建议的指标优先级

| 级别     | 指标                                                                      | 用途             |
| ------ | ----------------------------------------------------------------------- | -------------- |
| 主要终点   | 有效唯一属性数 \\(N^{unique}\\)                                                | 比较两算法的有效属性发现能力 |
| 共同核心描述 | 原始预测数 \\(N^{raw}\\)                                                     | 回答预测数量累积的直接问题  |
| 机制指标   | 首次新增数 \\(N^{new}\\)                                                     | 分析边际发现效率       |
| 辅助     | Pool 数、\\(P\_{\text{raw}}\\)、\\(R\_{\text{core}}\\)、E1/E2、Slot Coverage | 解释增长质量         |
| 诊断     | 输出上限、无效率、冗余率                                                            | 识别限制和偏差        |

这样既保留你最初关注的预测总数量，也避免得出“谁输出得多谁就更好”的结论。

## 八、统计分析：如何比较两个算法的逐轮增长？

### 8.1 为什么本次 31 段方案比较适合配对分析？

本实验具有一个很好的结构：

- 每段对话都有 11 条 A 发言。
- 每段对话都有 11 个前缀。
- 每个前缀都运行 Direct 和 ELARA。
- 两种算法面对完全相同的对话证据。
- 所有 k 都有相同的 31 段样本。

因此，整个数据是一个平衡的重复测量设计。

不能把 341 个前缀当作 341 段独立对话，因为同一段对话的 11 个前缀高度相关。

正确的独立抽样单位是：

\\[ \boxed{31\text{ 段对话}} \\]

### 8.2 分析 A：平均属性数量增长

在每个前缀长度 \\(k\\)，计算：

\\[ \overline N_m(k) = \frac{1}{31} \sum\_{i=1}^{31}N\_{i,m,k} \\]

分别对原始预测数和有效唯一属性数计算。

最终得到四条主要曲线：

- Direct 原始预测数。
- ELARA 原始预测数。
- Direct 有效唯一属性数。
- ELARA 有效唯一属性数。

其中有效唯一属性数量是评价两算法属性发现能力的主要依据。

### 8.3 分析 B：两算法的配对差值

对于每段对话、每个前缀：

\\[ D_i(k)= N^{unique}\_{i,E,k} - N^{unique}\_{i,D,k} \\]

两算法在第 k 个前缀的平均差值为：

\\[ \overline D(k) = \frac{1}{31}\sum\_{i=1}^{31}D_i(k) \\]

如果：

\\[ \overline D(k)>0 \\]

说明 ELARA 在该前缀平均发现更多有效属性。

如果差值随着 k 增大而扩大，则支持进一步研究 ELARA 的累积信息利用优势。

不过，绝对差值扩大并不必然意味着 ELARA 的单位信息处理效率更高，也可能与其整体输出预算或更高的初始提取能力有关。

因此建议在主分析之外，同步观察：

\\[ \overline D(11)-\overline D(1) \\]

这个量反映从第一条 A 发言到第十一条 A 发言，两算法的有效发现量差距扩大了多少。

### 8.4 分析 C：每轮新增属性

对每个 k 计算：

\\[ \overline N^{new}\_m(k) = \frac{1}{31} \sum\_{i=1}^{31}N^{new}\_{i,m,k} \\]

这能回答：

“增加第 k 条 A 发言时，算法平均首次发现多少个新的有效 B 属性？”

也可以计算 k=2–11 的平均新增速度：

\\[ M_m= \frac{1}{31\times10} \sum\_{i=1}^{31}\sum\_{k=2}^{11}N^{new}\_{i,m,k} \\]

不把 k=1 包含在平均新增速度中，因为它是初始信息状态，没有前一个非空前缀作为比较基准。

### 8.5 分析 D：事实池数量与模型发现量

除两算法曲线外，还应计算：

\\[ N^{pool}\_{i,k}=|G\_{i,k}| \\]

它表示截至当前前缀，AGD-EVAL 共同事实池包含多少个有效规范事实核心。

这样最终可以在同一张图上比较：

- Direct 有效唯一属性数。
- ELARA 有效唯一属性数。
- 当前 AGD-EVAL 事实池数量。

因为前缀 Pool 未必严格单调增长，所以不应强制把它变成一条始终上升的曲线。

特别需要明确的是，Pool 的增长不仅受到新增 A 发言的影响，也可能受到 Sweep 和审核器在不同前缀上发现候选事实的波动影响。

因此建议对事实池的非单调变化进行单独抽查，区分真实证据修正与模型审核不一致。

### 8.6 95% 置信区间与配对 bootstrap

建议沿用 AGD-EVAL 原始协议的设置：

| 参数           | 设置            |
| ------------ | ------------- |
| 重采样单位        | 完整对话          |
| 重采样数量        | 每次 31 段，有放回抽样 |
| Bootstrap 次数 | 2,000         |
| 随机种子         | 20261106      |
| 置信区间         | 95%，百分位法      |

每次 bootstrap 必须抽取完整的对话轨迹。

例如，某次重采样选到 `train_988`，就必须同时保留该对话 k=1–11 的全部结果，以及两个算法的全部配对结果。

不能分别对 Direct、ELARA 或不同前缀独立抽样。

对于增长假设，我建议报告以下三项预先指定的效应：

| 统计量                                  | 研究意义           |
| ------------------------------------ | -------------- |
| \\(\overline D(11)\\)                | 最终前缀两算法有效发现数量差 |
| \\(\overline D(11)-\overline D(1)\\) | 两算法差距是否扩大      |
| \\(M_E-M_D\\)                        | 两算法平均每轮首次新增量差  |

它们比对 11 个前缀分别做 11 次显著性检验更适合作为主结论。

如果还要报告每轮差异的置信区间，可以将其定位为描述性分析；涉及多轮显著性结论时，应考虑多重比较问题。

由于只有 31 段对话，建议以效应量、增长轨迹和置信区间为主，不把某个单独前缀是否达到 \\(p<0.05\\) 作为核心结论。

## 十、实施中的质量控制

这次实验最容易出问题的地方不是数量计算，而是前缀证据判定与跨轮事实匹配。

建议设置四组质量检查。

### 10.1 信息泄露检查

对全部 341 个前缀验证：

- 模型请求中没有 B 发言。
- Sweep 请求中没有 B 发言。
- Support 引用的 `turn_id` 必须属于当前前缀。
- Pool 不得引用未来发言。
- 跨前缀事实对齐不能回填未来证据。

对于第 k 个前缀，合法证据 ID 只能属于：

\\[ \\{1,3,5,\ldots,2k-1\\} \\]

如果支持证据中出现了 `turn_id=2k+1`，应立即判定为未来信息泄露或数据组织错误，并阻止该任务进入评分。

### 10.2 属性审核一致性检查

重点抽查：

- E1 与 E2 是否混淆。
- E2 与证据不足的 E3 是否混淆。
- A 的属性是否错误归属于 B。
- 开放问题是否错误转化为确定事实。
- 同一事件的时间、状态、数量是否被错误合并。
- 原始 claim 中无依据的细节是否在原子化中被删除。

### 10.3 跨前缀事实匹配检查

建议优先人工复核以下情况：

- 相同属性在相邻前缀被分配了不同统一 ID。
- 不同事件被错误合并。
- 属性首次出现位置不合理。
- 某个属性在一轮消失、下一轮又出现。
- 属性核心被错误拆成多个事实。
- 具体 slots 被当作新的独立事实。

### 10.4 人工复核方案

AGD-EVAL 原始正式评价尚未完成人工校准，因此这次不宜将自动判定结果直接称为人工验证后的真值。

对于 31 段的小规模实验，建议在自动评价完成后进行分层人工抽样。

例如：

- k=1–3：早期证据稀疏前缀。
- k=4–8：中期信息累积前缀。
- k=9–11：后期信息丰富前缀。

建议至少抽取 6 段对话，对其全部 11 个前缀进行重点核验，覆盖 66 个前缀；再针对其余对话中出现的跨前缀冲突、UNCERTAIN、E2 边界案例追加审核。

这是一项建议的人工复核设计，不是原始 AGD-EVAL 已规定的抽样比例。

复核时应盲化算法来源，优先由两位标注者独立审核争议事实，再对分歧进行裁决。报告自动与人工一致率、主要错误类型以及修正前后的关键指标变化。

## 十五、这项实验最终能得出什么结论？

本实验结束后，最有价值的不是简单报告 ELARA 比 Direct 多输出了几条属性，而是能够分别回答三个层次的问题。

第一层：预测数量增长。

随着 A 从 1 条发言增加到 11 条，两种算法的平均原始预测数量分别如何变化？是否出现平台期？

第二层：有效信息增长。

增加的原始预测有多少真正转化为 E1/E2 支持的不同属性？与当前可支持的事实池增长速度相比如何？

第三层：算法差异及增长机制。

ELARA v1 是否在较长前缀上展现出更大的有效发现量优势？这种优势主要来自新增 E1 明示事实、E2 隐式事实，还是不同的输出数量上限？

如果实验观察到：

- ELARA 的原始输出数量增长更快；
- 有效唯一属性数也增长更快；
- 后期仍能够首次发现更多有效属性；
- 这种差距在输出上限敏感性分析后依然存在；

那么可以较有依据地说：在这 31 段长度为 21 条发言的 DailyDialog 对话上，ELARA v1 对累积 A-only 信息表现出更强的有效属性发现能力。

但如果只看到原始 claim 数量增加，而有效唯一属性数量没有明显增加，就只能说明 ELARA 的输出规模更大，不能认为其获得了更多有证据支持的信息。

同样，如果两算法有效数量都随着前缀增长，但差值基本稳定，则说明两者都在利用新增上下文，不能进一步声称 ELARA 的相对优势随着对话变长而扩大。

我建议将这份设计作为第一阶段探索性实验协议，并将“341 个前缀共享事实池的构建”和“31 个跨前缀事实索引的准确性”列为最高优先级。 这两部分正确之后，属性数量、首次新增数和配对增长曲线都可以用确定性的统计程序计算，而不需要再次调用 Qwen 重新判断。
