# 本轮升级结论

298 段 A→B 完整实验已完成，评价始终使用 prompts-v2.py 与原 score_item/four_metrics。最终推荐分层融合 v3，保留 v1 主干，仅追加 v2 复核为 E1 的直接描述。模块接口为 pipeline(client,item)。

| 方法 | Precision | Recall | Grounded Recall | 严格平均 token |
|---|---:|---:|---:|---:|
| 原 v1 | 19.8198% | 14.9660% | 32.8244% | N/A |
| v2 全量覆盖扩张（未达精度目标） | 14.2691% | 20.9184% | 45.4198% | N/A |
| v2 E1-only 消融（原匹配子集，不是新在线评审） | 28.0120% | 15.8163% | 35.1145% | N/A |
| v3 分层融合（新在线评审） | 20.1141% | 18.8776% | 41.2214% | N/A |

v3 相较 v1 的 Recall 增益为 3.9116 个百分点，Grounded Recall 增益为 8.3969 个百分点，恢复真实参考由 88 增至 111，有据参考由 86 增至 108。Precision 为 141/701，仍高于本表原八算法和 v2 全量扩张版，但仅高于 v1 0.2943 个百分点。

精度差异的配对对话 bootstrap 95% 区间为 [-1.9281,+2.5027] 个百分点，尚不能宣称统计上稳健领先。两个召回增益的区间分别为 [1.9855,5.8520] 和 [4.2105,12.7124] 个百分点。以上区间条件于已记录输出，未校正同一 298 段的适应性开发或模型随机性，也不是独立留出验证。

瓶颈：v1 丢弃 137 条无精确引用候选（其中 96 条可仅用空白定位恢复），65 条被问号硬过滤，保留输出有 96 条 broader 和 20 条 narrower。v2 修复覆盖后，E1 分支正确 93/332，而 E2 仅 30/530（5.6604%），说明盲目扩展隐式推断会破坏精度。v3 因此采用保守主干和高精度直接补充，不接入扩张的 E2 分支。

成本：严格沿用未知 usage 返回 null 的规则，v3 有 34 次源推断尝试缺失 usage。三阶段已知 token 1,199,268，已知用量下界为 4,024.389262/段，不能当成精确均值。v3 的源推断响应按相同请求哈希复用，没有重新收费；部署成本仍按完整三阶段归因。本轮新推断已知用量（含中止接口适配轮，不含评价）为 1,037,349；详见 development_cost_audit.json。

61 项测试通过，8 个结果文件离线重放哈希一致。原八算法行逐字段不变；原 v1 保护的 1,623 个历史文件不变。v3 本轮核验 2,905 个文件未变化，另一个活跃 EFCR v2 追加实验的独立文件按明确记录排除，未改动其内容。

首批 JSON 示例缺字段导致的中止轮及全部 v2 扩张失败结果均保留。v3 新在线评审有 16 条 broader/narrower/none 的 prompt 格式偏离，仍沿用历史解析器，不改写判断；严格主表本就不计这些关系，详见 prompt_contract_audit.json。
