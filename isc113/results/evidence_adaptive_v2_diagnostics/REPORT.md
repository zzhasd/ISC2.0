# v1 瓶颈诊断与 v2 预设设计

诊断数据为既有 298 段 A→B 实验记录，以下是描述性分析，不是独立留出验证。

| 阶段 | 数量 | 解释 |
|---|---:|---|
| 模型原始候选 | 646 | 上一轮首个有效响应 |
| 引用不精确删除 | 137 | 其中 96 条可仅用空白字符对齐恢复；其余 41 条不能据此修复 |
| 问号结尾删除 | 65 | 包含开放问题，也包含明确称呼/预设/陈述子句，不能把 65 条全部视为真属性 |
| 最终输出 | 444 | 没有触及每段 8 条上限，单纯扩大 cap 不能解决既有丢失 |
| equivalent | 88 | 严格主表命中 |
| broader | 96 | 表述粒度过宽或参考含有不可见细节；不能照参考补写 |
| narrower | 20 | 过度具体/时间事件限定不一致 |
| none | 240 | 仅扩充候选会同时扩充低效输出 |

96 条 broader 中，53 条关联至少一个 E1/E2 参考；引用边层级分布为 {'E3': 46, 'E2': 33, 'E1': 28, 'E4': 1}。关联不代表所有缺失细节可由 A 恢复，不能把宽松表上涨当成严格 Recall 的提高。

升级预设：

1. 不改动原始 A 文本。引用修复仅去除空白进行唯一定位，再返回原文精确子串；不做大小写、标点、错码或语义替换。歧义定位保持无效。
2. 生成阶段覆盖所有可见轮次，检查直接描述、明确称呼、强预设和跨轮关系；取消“优先 0–6 条”提示，最大 12 条，但不强制凑数。
3. 第二阶段独立复核说话者归属、反事实可否证、时间模态、事件对象和特异性；保留有据的必要限定，避免将同一事件拆成多个过宽片段。即使候选为空也重新检查可见轮次。
4. 删除问号硬过滤，由语义复核区分未回答的问题与问句内独立有据命题；最终只保留精确引用有效的 E1/E2 结果。
5. 温度 0，生成/复核各 thinking_budget=512、max_tokens=3072；评价仍是 prompts-v2.py + 原 validate_matches/score_item/four_metrics。

不读取参考、完整 B 或匹配结果参与推断。没有逐样本规则、参考事实模板、按测试指标搜索 confidence 阈值或更改评价器。v2 一次冻结并完整运行 298 段，与原八算法逐字段保存的行对比。目标为严格 Precision 至少达到 v1 的 88/444，同时提高 88/588 的 Recall 和 86/262 的 Grounded Recall；是否达标须等实际结果，不能预先保证。
