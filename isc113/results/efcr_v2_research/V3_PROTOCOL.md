# EFCR 下一版候选协议（研究建议，尚未执行）

本协议不是已完成实验，不提供性能保证。298 段已作为开发集分析，新数据上的泛化需另行验证。旧六算法、EFCR v1/v2 的源码、预测、匹配和主表继续冻结。

## 优先实验：定位核验器的作用

固定 v2 的 1276 条生成候选，单独比较：

- G0：原裁决器及事前固定门槛。
- G1：保留同样候选和原文，但隐藏生成器 confidence、proposal_sources 及其他排序暗示；候选顺序固定并记录。
- G2：针对关键槽位提出中立核验问题，从可见原文独立回答。核验器不看候选答案和生成器分数，允许 unknown。之后做结构化条件对齐。

G1 可隔离分数/来源提示的影响，G2 检验验证任务重构。都不将 147 条未判分排除候选视为已知错误。若要估计生成候选的严格覆盖上限，需要在独立诊断目录补充这些候选的语义匹配。

所有重用生成的 task_ids 都按实际已有生成成本计入对应方法，新增核验尝试完整计费。新匹配仍使用原 prompts-v2.py、score_item、four_metrics，独立存档。

## 完整候选架构

第一阶段一次读取全部 A-only 原文，覆盖显式属性和保守隐含属性，输出证据表和完整属性框架：

```json
{
  "subject": "B",
  "predicate": "一个有信息量的属性或事件",
  "object": "证据支持的对象或值",
  "time": "可为空，保留原时态/范围",
  "quantity": null,
  "negation": false,
  "modality": "asserted|qualified|intended|conditional",
  "evidence_ids": ["s1"],
  "verification_question": "不预置答案、允许未知的关键条件问题"
}
```

第二阶段只读原文与核验问题，独立给出关键条件答案及证据跨度。核对主体归属、对象、时间、否定、数值、模态。不要把原命题改写成更模糊的参与描述；不支持则拒绝或 unknown。语义对齐不明确的少量项可追加专门核验，其余结束，所有调用记录完整保留。

这里的一致性是两个步骤恢复的条件是否相容，不等于原来两个完整生成通道的同文一致，也不能预设两者统计独立。更改调用结构后，旧 source_aware 阈值不能未经验证直接照用。

渲染器仍输出既有 claims、certainty、mechanism、confidence、evidence 与 task_ids 接口，引用由原文跨度切片获取。不得读取完整 B 对话、参考属性、互联网人物资料或评价匹配结果。

## 固定比较和四指标目标

基线采用本轮联合匹配的旧 EFCR 与 v2；新评价独立保存并在比较时让同文预测共享判断。主计分 equivalent-only，broader 仅作原有诊断对照。

研究目标是同时满足：Precision 不低于同轮旧 EFCR 的 18.65%，Recall 高于 v2 的 21.60%，Grounded Recall 高于 v2 的 46.18%，同时减少真实平均推断 token。它们是待检验目标，不是承诺结果。

如果新实验完整 usage 可得且均值低于 v2 已知下界 4342.49，才可直接确认成本比 v2 更低；如果有缺失，则仍按原规则报告 null 和已知下界，不补零。

阈值在开发或校准部分确定后固定，再报告其余数据上的结果。已经反复分析过的本批 298 段不能通过重新随机切分变成真正未见测试。组件消融和预算报告必须保留失败与退化结果，不只展示获胜变体。
