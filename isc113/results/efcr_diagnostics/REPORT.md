# EFCR 召回诊断与改进可行性分析

结论：存在同时保持 Precision 优势并提高两项召回的空间。现有结果最支持的方向是补足直接属性覆盖、保留证据已支持的细节、减少无效修复和引用格式损失。不能只放松验证器或增加输出上限。离线缓存组合已经出现三指标同时提高，但包含评价器波动，不能当成新的独立在线实验。

本分析没有新增 API 请求，没有更改原六算法、固定参考、评价 prompt 或计分规则。所有指标仍用 equivalent-only、原 score_item / four_metrics、298 段分母、588 条参考和 262 条有据参考。只新增诊断产物。EFCR 推断逻辑保持不变；运行器的历史完整性检查修正为允许新增独立分析文件，仍逐一核验原来的 980 个文件。

## 1. 两种 Recall 为什么低：先分清分母和缺口

全部参考有 E1=136、E2=126、E3=295、E4=31。E3/E4 共 326 条，占 55.44%。EFCR 的目标是从可见 A 轮次恢复有据属性，因此不能靠猜测这些隐藏细节来追求整体 Recall。只恢复全部 E1/E2 对应的整体 Recall 是 262/588=44.56%；这是有据覆盖的量级参照，不是模型绝对的数学上限。

EFCR 实际恢复 102/588 条参考，其中有据 97/262，另有 5 条非有据参考命中。Grounded Recall 低的直接来源是：

| 方法 | E1 命中/136 | E2 命中/126 | 有据总命中/262 |
|---|---:|---:|---:|
| EFCR | 81 | 16 | 97 |
| route1_only | 84 | 22 | 106 |
| dual_with_verifier | 86 | 28 | 114 |
| dual_without_verifier | 88 | 32 | 120 |

层级命中沿用原最大有据匹配结果中的 E1/E2 分配，不另做两个独立最大匹配后相加。EFCR 漏掉的 165 条有据参考中，55 条为 E1，110 条为 E2。相对 dual_without_verifier 的 23 条有据命中差距中，16 条来自 E2。因此主要短板是隐含属性的有效覆盖和表达，而不是所有层级都同等下降。

63 段最终空输出含 64 条参考，其中只有 22 条是 E1/E2；剩余 143 条有据漏检发生在非空输出对话中。单纯减少弃答不足以解决问题。

## 2. 实际流水线损失

| 环节 | 数量 |
|---|---:|
| 首阶段生成候选 | 688 |
| 引用不精确被过滤 | 81 |
| 有效候选进入裁决 | 607 |
| keep | 517 |
| repair | 46 |
| reject | 44 |
| 最终输出 | 563 |

初次生成为空的对话为 40 段，最终为空为 63 段。没有一段触及 10 条候选上限，故提高上限没有当前实验依据。拒绝仅 44/607=7.25%，其中 14 条为引用/证据级别等程序性降级。现有记录不支持把召回低全部归咎于裁决拒绝。

81 条无效引用中，41 条只需消除空白差异就能在原轮次中找到对应文本。例如原文 `My friends ? Fat ?` 被模型写成 `My friends? Fat?`。另一些涉及数据中的 `��` 与模型恢复的英文撇号。这是技术性流失，但不能把 81 条或 41 条直接当成可恢复的正确属性；引用可定位不等于内容有据。

对被修改或拒绝的原始候选，只有 repair 的 6/46、reject 的 4/44 在已有缓存中存在完全同文的语义匹配，其余原始候选未被评价。不能断言这部分都错误，也不能给出“裁决误杀了多少正确属性”的完整数字。需要独立的候选级匹配才能作这个归因。

## 3. 比拒绝更明显的损失：泛化和过度拆分

最终 563 条预测的固定参考关系为：

| 关系 | 输出数 |
|---|---:|
| equivalent | 103 |
| broader | 155 |
| narrower | 25 |
| none | 280 |

103 条等价输出经最大一对一匹配恢复 102 条参考。`none` 仅表示未获固定参考匹配，不能据此认定现实中错误或没有可见证据。

155 条 broader 不获主表计分。作为诊断，沿用原来的 broader 宽松对照后，Recall 从 102/588 增为 223/588，Grounded Recall 从 97/262 增为 160/262。新增的 121 条参考、63 条有据参考说明表达粒度是显著问题，但不能把这些宽泛预测直接升级为严格正确。

具体案例 `train_1885`：A 明说 `You've had your nose buried in that book since last night`。参考为 B 从昨夜起一直沉浸于一本书，EFCR 拆成“B 正在读书”和“B 从昨夜起一直在读”。两条分别遗漏相关限定，均被判 broader。这里应该保留同一属性的动作、对象和时间，而不是把一个完整事实拆成互相缺条件的片段。

46 条 repair 中：equivalent=0、broader=10、narrower=3、none=33。删除 repair 的离线消融使 Precision 从 103/563=18.29% 提高到 103/517=19.92%，两个 Recall 完全不变。这表明当前 repair 分支尚未带来严格计分收益；不等于证明所有修复内容都不真实。

修复还可能引入新的主体错误。例如 `train_10306`，可见 A 自述已投票，某修复却把“已通过缺席选票投票”归到 B。原文引用有效和来源轮次有交集，并不能保证修改后的属性保留正确主体或确实是原命题的弱化。

## 4. 能否三指标同时提高：已有缓存的探索性组合

组合规则不读取参考：保留指定 EFCR 输出，追加 route1_only 中置信度至少 0.8 且引用有效的候选，再去重。阈值和变体是在本批 298 段上探索的；不是新的独立验证结果，也没有重新请求生成或联合语义评价。

| 探索方案 | Precision | Recall | Grounded Recall |
|---|---:|---:|---:|
| 原 EFCR | 18.29% | 17.35% | 37.02% |
| 仅移除 repair | 19.92% | 17.35% | 37.02% |
| 原 EFCR + 高置信 route1 | 20.16% | 21.26% | 45.80% |
| 移除 repair + 高置信 route1 | 21.24% | 21.26% | 45.80% |
| 上一方案再排除大小写、空白、句末句点差异造成的重复 | 20.17% | 20.75% | 44.66% |

最后一行共 813 条输出，164 条等价输出，恢复 122 条参考、117 条有据参考。相对原 EFCR，三指标分别增加 1.88、3.40、7.63 个百分点。原六算法最高 Precision 为 16.90%，此探索结果仍高于它。

最后一行相对 EFCR 多恢复的参考关联中，11 条原来已有 broader/narrower 关联，9 条原匹配中无关联；这不是完全区分“真实漏提”和“判分波动”的人工语义标注。可见的补足方向包括：`train_3101` 的目前就读 PCC、`train_4807` 的称呼 Peter、`train_2788` 的借阅一个月归还期限、`train_7699` 的应聘翻译岗位。

只追加高置信 route1 的版本增加 320 条输出，其中 75 条获等价计分，追加部分的计分 Precision 为 23.44%，高于 EFCR 的 18.29%，因此能够在增加覆盖的同时提高整体 Precision。这比无差别放开候选更有实验支持。

不能忽略原指标的重复计数方式：Precision 按输出断言计数，Recall 才做最大一对一匹配。最后一行的正确输出增加 61 条，而恢复参考只增加 20 条；不能把 61 条都称为新发现的独立属性。

## 5. 评价波动限制了结论强度

EFCR 与六算法的匹配缓存中，共有 149 个同一对话、完全同文的预测，其中 32 个得到不同的关系或参考 ID。两轮使用相同 prompt 文件和参考，但候选清单、调用时间不同；仅凭日志不能把波动归因给某一个因素。

此外，`train_5244` 中 EFCR 的 `The hidden partner is a waiter.` 被判 broader，而 route1 的同句无句末句点版本获 equivalent。原 EFCR+route1 的一部分收益只是这种计分不稳定。上表末行移除了这类最直接的重复后仍有提升，但没有消除全部语义等价表达的评价波动。另有个别数值不同却被判 equivalent 的案例，已保留在诊断记录中，未改写历史标签。

所以当前可以说“有保住 Precision 并增召回的具体候选方案”，还不能说“新版 EFCR 已被独立实验证明优于旧版”。离线 bootstrap 文件只提供探索性区间，没有修正多方案搜索，也不能消除匹配噪声。

## 6. 建议下一轮的具体改动

1. **优先补足覆盖，保留严格门控。** 加一个直接事实扫描通道，重点覆盖称呼、角色、所属关系、当前活动、计划、对象与时间。优先使用高置信、精确引用的候选。不要直接把 dual 的全部预测并入，也不要全局降低 E1/E2 门槛。
2. **修复只删无据限定，保留已被证据支持的细节。** 同一谓词关联的时间、对象、数量、否定和模态应随该属性保留。修复不能凭空改主体、换属性或只添加“可能”来保留原来的猜测；没有有信息量的有据修复时直接拒绝。可以先把 repair 暂停作为消融，检验其是否有独立收益。
3. **引用用原文跨度表示。** 让模型选择原 turn_id 及可定位跨度，由渲染器取回原字符串。对白空白格式只允许唯一且可逆的定位恢复，再提交裁决；不修改原输入、不恢复乱码的含义、不放宽主体和蕴含检查。
4. **先统一评价条件再比较新版。** 在独立诊断目录中，把旧版和候选新版同一对话的去重预测放进同一匹配清单，使用不变的 prompts-v2 和计分规则；同文预测共享同一个判断。对矛盾匹配、数字和主体归属另做人工抽查，保留原始判分不覆盖历史。
5. **分开做消融。** 引用定位、支持细节保留、直接通道补充、repair 开关分别测试，再测组合。当前 298 段用于诊断和开发；候选规则固定后还需新的未用于调参的数据，才能检验泛化和稳定性。置信度是排名分数，不应把 0.8 解释成 80% 的真实性概率。

复现核心统计：`python -B -m isc113.analyze_efcr`。主要原始诊断文件包括 `stage_counts.json`、`candidate_trace.json`、`claim_relations_by_group.json`、`recall_by_reference_level.json`、`offline_ablations.json`、`punctuation_dedup_sensitivity.json`、`exact_text_matcher_conflicts.json`、`quote_formatting_diagnosis.json` 和 `analysis_integrity.json`。
