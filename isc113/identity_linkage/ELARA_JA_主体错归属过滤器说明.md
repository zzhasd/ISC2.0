# ELARA v1 → 一次 A 自述错归属过滤 → Summary

## 这次修改后的唯一规则

> **只删除可以明确证明：ELARA v1 将 A 对自己所说的某个事实错误归到了 B 身上的属性。**
>
> **主体不明、语义不确定、B 证据不足、第三人或泛化陈述等情况，一律放行。**

本模块只过滤一类错误（`A_SELF_MISATTRIBUTION`），并非对所有候选进行真实性判断。其输入是 **ELARA v1 的已有 B 候选属性、逐条引用、以及 A 发言的局部上下文**。不再抽取属性、不改写属性、不修改 ELARA v1，也**不在 Summary 后再审核**。

流程：

```text
ELARA v1（不改动）
    ↓ 原始候选 claim、source_id、原文 quote
日语 A→B 自述错归属过滤器（仅一次）
    ├─ 明确将 A 自述误写成 B 属性 → DROP
    └─ 其他全部，包括 UNKNOWN → KEEP
    ↓ 只把 KEEP 的原始属性送往下游
Summary（不增加后置审核）
```

### 与旧版的关键区别

| 判定对象 | 旧版严格过滤 | **新版（本次要求）** |
|---|---|---|
| A 明确在描述自己的同一个事实，却被写成 B | DROP | **DROP** |
| A 省略主语，但上下文明确是自己的经历 | DROP | **DROP** |
| 主体不明 `UNKNOWN` | DROP | **KEEP** |
| 找不到足以证明 B 拥有属性的证据 | DROP | **KEEP** |
| 说的是 B／直接对 B 发问 | 可能 KEEP | **KEEP** |
| 说的是第三方／泛化事实 | DROP | **KEEP** |
| 「私も」暗示某个双方可能共有的宽泛属性 | 默认 DROP | **不明确误归属则 KEEP** |
| 不完整／引用不足以支持明确 A 自述 | DROP | **KEEP** |

## 日语语义的具体判断

**关键：话语由 A 说出，不等于事实主体一定是 A。** 过滤器必须判断 ELARA claim 所写的那个具体事实，是否来自 A 的明确自述。

1. **显式自述**：`私/僕/俺/わたし/自分/うち/我が家`，应识别代词支配的谓词和所属对象；如果属性内容与 A 自述的具体事实相同且被归到 B，删除。只有出现代词但 claim 实际在描述 B，则不能删。
2. **零主语**：`新婚旅行でハワイに行っただけですね`、`車でちょっと遠出とかよくします`、`兵庫出身で今実家が大阪にあります` 等，若上下文足够明确是在 A 描述自己的经历，并被误写成 B，删除；若主体不明确，放行。
3. **助词「も」的范围**：`焼き芋の香りも好きです` 的「も」附在“香味”，不能用于推断 B 也喜欢这种香味；若确定是 A 喜好的自述且被写成 B，删除。`私も20代です` 则可能暗示 B 也处于二十多岁，`B is in their 20s` 不属于明确的 A→B 错误，应放行。但不能由 `私も` 把 A 独有的年份、旅行、家庭细节转移给 B。
4. **A 谈论 B**：`どんな絵を描かれるのですか？` 等，虽然发言人是 A，但可能以 B 为语义主体；无论证据强弱，除非明显从 A 的个人事实复制，否则放行。
5. **复合 claim**：一条 claim 同时包含 B 属性和明确错抄自 A 的个人细节时，整条删除（不修补或拆分）。
6. **不确定性优先放行**：不要用“无法证明 B 有这个属性”作为删除理由。这个过滤器只负责找出明确的 A 自述误归属，其他画像问题留待单独评价。

## 例子

| ELARA claim | A 的原话 | 新版处理 |
|---|---|---|
| B 喜欢烤红薯的香味 | 焼き芋の香りも好きです | **DROP**：A 的喜好自述，不是说明 B 喜好的「私も」 |
| B 去夏威夷度蜜月 | 新婚旅行でハワイに行っただけですね | **DROP**：明确 A 的生活经历 |
| B 的老家在大阪 | 兵庫出身で今実家が大阪にあります！ | **DROP**：明确 A 的出身和家庭背景 |
| B 是二十多岁 | 私も20代です | **KEEP**：「我也」可能关联 B，不能确定为错归属 |
| B 在绘画 | どんな絵を描かれるのですか？ | **KEEP**：A 在对 B 提问，不是 A 的自述 |
| B 是学生 | そうですね。 | **KEEP**：没有足够信息判为 A 自述，虽然也未证明 B 确实是学生 |

## 技术实现

主文件：`elara_ja_subject_filter.py`，测试文件：`test_elara_ja_subject_filter.py`。

- 模型先识别实际主体（`A/B/MIXED/THIRD/GENERIC/UNKNOWN`），返回 `KEEP/DROP`、判定理由、以及在 `DROP` 时引用的**原始 A 自述片段** `self_quote`。
- 程序最终只准许这两种情形删除：`actual_owner=A` 且 `reason_code=A_SELF/A_ZERO_SELF`；或 `actual_owner=MIXED` 且 `reason_code=MIXED_A_B`。
- 此外，删除必须提供 `self_quote`，并且它是该原始候选 evidence 里可精确匹配的日语文本；若来源不合法、没有引用片段、主体不明、理由不一致，则**改为 KEEP**。此约束用来避免模型过度删除，但不等于程序已独立验证日语谓词归属。
- 如果模型输出 JSON 格式损坏、source_id 缺漏等，流程报错而不是偷偷把整批未经处理的内容称为已过滤结果。这与语义上的 `UNKNOWN → KEEP` 是两件事。
- 每一条 ELARA 原始 claim 单独过滤，再做去重。所有原始记录及 `source_id` 保留；删除及模型标签单独写入审计日志。
- 对下游 Summary 输出的 `deduplicated.json` 使用相同数据结构。Summary 接入时需注意将 prompt 中写死的候选总数更新为实际过滤后数量（如果有固定数量的要求）。

### 运行命令

```bash
python test_elara_ja_subject_filter.py -v
export QWEN_API_KEY='...'
python elara_ja_subject_filter.py \
  --source /path/to/runs/portrait_summary_20261107 \
  --out /path/to/new_filtered_run
```

脚本要求 Python 3.11+；使用可配置的 Qwen OpenAI-compatible API，且不会修改输入目录。

输出：`attributes_filtered.json`（保留的原始 claim）、`deduplicated.json`（供 Summary 输入）、`subject_decisions.json`（每条归属判断）、`subject_filter_report.json`（总数与原因统计）、`inputs.json`（原文副本）。
